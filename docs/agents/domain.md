# Domain docs

This package uses a single-context documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/`.
- Proceed silently when either source does not exist.

## Vocabulary and decisions

Use terms from `CONTEXT.md` in issue titles, proposals, and tests. If a requested concept is not
defined there, treat that as a possible domain-modeling gap. If a change conflicts with an ADR,
surface the conflict explicitly rather than silently overriding it.
